# R1 K03-07: physical, reserved and available stock

The existing acceptance requires three separately labeled quantities; available is physical minus active reservations. Rich product list and full card now read product stock and the selected product's `ACTIVE` reservation sum under the same verified SERIALIZABLE/HOLDLOCK transaction. RELEASED and DISPATCHED reservations do not count. The existing indexed reservation table and permissions are reused, without DDL or new grants.

The shared BigInt projection keeps native base-unit decimal(18,3) values exact, preserves negative availability, and never rounds, clamps or substitutes zero for unknown data. SQL zero is only the aggregate over a known empty matching reservation range. Malformed, missing or negative reservations fail closed. The readonly card supports paired validated stock fields while legacy cards lacking both display unknown; the rich list requires and validates them in API and browser core. Physical series equivalents remain derived from physical ADET, separately labeled from available stock.
