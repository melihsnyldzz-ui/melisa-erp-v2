# R1 ADET base and full series multiplier

Authority: DES-04 in the existing `ERP-uygulama-tasarimi-2026-11-05.json`, based on OS DEC003 and the 26 September decision: ADET is the main unit; 8 ADET equals two 4-piece series. This resolves the older demo's package-based stock projection. The previous clarification question requires no further answer. The existing central K03-03 requirement is unchanged.

New rich product creation can supply `seriesFactorExact8`, an integer 2 through 1,000,000. It creates an ADET main unit at factor 1 and exactly one immutable SERİ secondary unit in the existing local units table. Both rows, their IDs/product parents/labels/factors/main flags, and the native ADET price link are checked within the same transaction. The independent SQL-store guard refuses a missing secondary row. No DDL, grants or factor-edit route is added. Missing optional fields are not inserted into old body hashes, pending requests or rejected drafts; old committed replies retain their stored shapes.

Physical stock, stock movements, invoice quantities, cost and native price remain in the main ADET unit. The card and list derive complete series plus remaining ADET using BigInt; fractional and negative physical stock is represented without rounding or claiming sellable/reserved stock. An unknown multiplier is not treated as 1. A series has no invented separate stored price.

The sales selector permits complete integer SERİ quantities for products with a verified secondary unit; individual pieces use ADET. The entered unit ID/factor/quantity is kept beside its exact converted ADET quantity in the durable request. The locked SQL secondary-unit identity and factor join the preview revision. Server preparation verifies the selected product/unit, factor and equality with the ADET quantity before native invoice creation. Existing native main-unit/factor-1 and decimal/Number parity guards remain intact. Unknown-response retries preserve the same body and never recalculate using a new factor.

For series selections, one immutable audit detail with actor, invoice, UUID, entered series quantity, multiplier and ADET quantity is inserted and read back within the draft transaction. Old journal replay returns before selection/audit work. Invoice history stores the converted ADET quantity and is not repriced or reconverted from current product metadata. UI conversion text and the queued body both use the authoritative preview rather than a stale list cache.
