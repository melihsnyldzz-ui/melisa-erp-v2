# R1 traced initial stock reason

K03-05 extends the existing product-creation transaction without DDL or grants. The rich GUI asks for a bounded reason when initial stock is positive. A structured `desktop-product-opening-v1` detail is stored in the existing audit_logs.after_json: product ID, actual movement ID, actor, request UUID, reason, quantity, TRY cost/amount and date. The UUID remains in audit_logs.reason so existing audit/request lookup is unchanged. Both coordinator and SQL-store guard require exact same-transaction audit readback before finishing the journal.

The optional request property participates in the normal body hash when present. Old bodies are not rewritten. A fresh rich opening using the older request format receives the explicit action-derived reason `Yeni ürün kartı başlangıç stok girişi` after the journal replay check; this text is not added to its body/hash. Previously committed requests replay without metadata changes. Existing movements are not backfilled. Zero opening stock cannot carry a reason or produce an opening detail.

Readonly product-card access retains current normal product.view + product.edit authorization. The optional opening detail is accepted only after the persisted audit's product/actor/UUID and the actual stock movement's parent, actor, quantity, cost, amount, currency, date and movement type agree. Invalid or foreign detail fails closed; no opening reason is invented for an old card.

Source verification: 65 focused test files passed under the offline guard and the guarded green-screen build passed. Added checks cover lost acknowledgement and replay, reason/body conflict, invalid date/reason, wrong opening parent/reason readback rollback, direct-store audit omission, legacy request compatibility, actual HTTP application/auth/coordinator/store assembly with a synthetic driver, readonly movement matching, and escaped display.
